Nếu áp dụng phương pháp chia ngẫu nhiên (random splitting) truyền thống:

Giải nghĩa từ khóa chuyên môn

    Session Key (Mã phiên quay): Chuỗi nhận dạng duy nhất cho một chuỗi ghi hình liên tục. Ví dụ, ảnh vlcsnap-2025-02-18-23h08m14s528.jpg được quy về phiên vlc-2025-02-18-23 (phiên quay lúc 23h ngày 18/02/2025).
    Deterministic Splitting (Phân chia tất định): Thuật toán sắp xếp các phiên bằng mã băm SHA256 kết hợp hạt giống seed="day10" và số salt. Mọi học viên chạy trên máy tính nào cũng sinh ra phân bổ split giống hệt nhau, đảm bảo tính công bằng khi chấm điểm.
    Phân bố lớp lệch (Class Imbalance across Splits): Do gom theo phiên quay thực tế, phân bố số lượng vật thể giữa các split sẽ không đồng đều. Chặng 2 — Định dạng Nhãn Grounding và Đánh giá Baseline E0 Zero-shot
Bản chất và vấn đề cần giải quyết

Mô hình Vision-Language Model như Qwen3-VL không sinh ra các tensor toạ độ thông qua tầng hồi quy như YOLO hay Faster R-CNN, mà sinh ra toạ độ dưới dạng các token từ vựng văn bản (textual tokens).

Để mô hình hiểu và sinh toạ độ ổn định:

    1. Thang đo chuẩn hoá 0–1000: Qwen3-VL sử dụng quy ước biểu diễn toạ độ bằng số nguyên trong đoạn [0, 1000], đại diện cho tỷ lệ phần nghìn của chiều rộng và chiều cao ảnh. Việc dùng thang đo chuẩn hoá giúp mô hình học được mối tương quan không gian mà không bị phụ thuộc vào độ phân giải tuyệt đối của từng bức ảnh.
    2. Thứ tự sinh box tất định (Deterministic Ordering): Nếu trong một bức ảnh có nhiều hư hại mà thứ tự xuất hiện của chúng bị xáo trộn ngẫu nhiên giữa các mẫu, mô hình autoregressive sẽ bị nhiễu loạn khi dự đoán token tiếp theo. Do đó, các bounding box phải được sắp xếp cố định theo thứ tự từ trên xuống dưới, từ trái sang phải: ưu tiên y1 tăng dần, sau đó đến x1 tăng dần.

Giải nghĩa từ khóa chuyên môn

    Visual Grounding: Nhiệm vụ liên kết ngôn ngữ tự nhiên với vùng không gian tương ứng trong ảnh. Đầu ra grounding của Qwen3-VL là nhãn lớp kết hợp mảng 4 phần tử [x1, y1, x2, y2].
    BitsAndBytes NF4 (NormalFloat4): Phương pháp lượng tử hóa thông tin 4-bit tối ưu lý thuyết cho các trọng số mạng nơ-ron phân phối chuẩn, giúp nén LLM từ 16-bit xuống 4-bit mà không làm suy giảm đáng kể năng lực suy luận.
    Skip Modules (llm_int8_skip_modules): Cờ cấu hình sống còn trong BitsAndBytes:

llm_int8_skip_modules = ["visual", "lm_head"]


Giữ nguyên khối thị giác ViT, Projector và đầu ra lm_head ở định dạng dấu phẩy động 16-bit (fp16). Nếu để BitsAndBytes lượng tử hoá cả ViT, các trọng số của Projector sẽ bị khoá ở dạng 4-bit và hoàn toàn không thể mở ra để huấn luyện gradient ở các thí nghiệm E2 và E3.
Các bước thực hiện chi tiết

    1. Viết hàm chuyển đổi nhãn từ YOLO sang Grounding JSON thang 0–1000 trong notebook:

import json


def yolo_to_box(label: str, yolo: list[float]) -> dict:
  xc, yc, w, h = yolo  # Chuẩn hoá [0, 1]
  x1 = int(round(max(0.0, min(1000.0, (xc - w / 2) * 1000))))
  y1 = int(round(max(0.0, min(1000.0, (yc - h / 2) * 1000))))
  x2 = int(round(max(0.0, min(1000.0, (xc + w / 2) * 1000))))
  y2 = int(round(max(0.0, min(1000.0, (yc + h / 2) * 1000))))
  if x2 <= x1:
    x2 = min(1000, x1 + 1)
  if y2 <= y1:
    y2 = min(1000, y1 + 1)
  return {"label": label, "bbox_2d": [x1, y1, x2, y2]}


def objects_to_answer(objects: list[dict]) -> str:
  boxes = [yolo_to_box(o["label"], o["yolo"]) for o in objects]
  # Sắp xếp ổn định: trên -> dưới (y1), trái -> phải (x1)
  boxes.sort(key=lambda b: (b["bbox_2d"][1], b["bbox_2d"][0]))
  return json.dumps(boxes, separators=(",", ":"))

from transformers import (

    BitsAndBytesConfig,

quantization = BitsAndBytesConfig(

    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,
    llm_int8_skip_modules=["visual", "lm_head"],
)
model = Qwen3VLForConditionalGeneration.from_pretrained(
    "Qwen/Qwen3-VL-4B-Instruct",
    quantization_config=quantization,
    device_map="auto",
)
processor = AutoProcessor.from_pretrained("Qwen/Qwen3-VL-4B-Instruct")
processor.tokenizer.padding_side = "left"

    Chat Template: Quy tắc bao đóng hội thoại của mô hình bằng các token đặc biệt (<|im_start|>user, <|im_end|>, <|im_start|>assistant).

def encode_example(image, prompt, answer, processor):
  user_msg = [
      {
          "role": "user",
          "content": [
              {"type": "image", "image": image},
              {"type": "text", "text": prompt},
          ],
      }
  ]
  full_msg = user_msg + [{"role": "assistant", "content": answer}]

  prompt_enc = processor.apply_chat_template(
      user_msg,
      tokenize=True,
      add_generation_prompt=True,
      return_dict=True,
      return_tensors="pt",
  )
  full_enc = processor.apply_chat_template(
      full_msg,
      tokenize=True,
      add_generation_prompt=False,
      return_dict=True,
      return_tensors="pt",
  )

  n_prompt = prompt_enc.input_ids.shape[1]
  # Kiểm tra tiền tố bảo đảm tính nhất quán
  assert (full_enc.input_ids[0, :n_prompt] == prompt_enc.input_ids[0]).all()

  # Tạo nhãn và mask toàn bộ phần prompt/ảnh bằng -100
  labels = full_enc.input_ids.clone()
  labels[0, :n_prompt] = -100

  return {
      "input_ids": full_enc.input_ids[0],
      "attention_mask": full_enc.attention_mask[0],
      "pixel_values": full_enc.pixel_values,
      "image_grid_thw": full_enc.image_grid_thw,
      "labels": labels[0],
  }

def collate_fn(batch, pad_token_id=151643):
  input_ids = torch.nn.utils.rnn.pad_sequence(
      [b["input_ids"] for b in batch],
      batch_first=True,
      padding_value=pad_token_id,
  )
  attention_mask = torch.nn.utils.rnn.pad_sequence(
      [b["attention_mask"] for b in batch], batch_first=True, padding_value=0
  )
  labels = torch.nn.utils.rnn.pad_sequence(
      [b["labels"] for b in batch], batch_first=True, padding_value=-100
  )

  # Nối tensor ảnh, KHÔNG padding
  pixel_values = torch.cat([b["pixel_values"] for b in batch], dim=0)
  image_grid_thw = torch.cat([b["image_grid_thw"] for b in batch], dim=0)

  return {
      "input_ids": input_ids,
      "attention_mask": attention_mask,
      "labels": labels,
      "pixel_values": pixel_values,
      "image_grid_thw": image_grid_thw,
  }

Chặng 4 — Các Thí nghiệm Finetune E1, E2, E3 (LoRA LLM, Projector, LoRA ViT)
Bản chất và vấn đề cần giải quyết

Một câu hỏi kiến trúc cốt lõi trong Vision-Language Model là: Khi tinh chỉnh cho một bài toán thị giác chuyên biệt (như phát hiện ổ gà), khối nào cần được cập nhật trọng số?

Mô hình Qwen3-VL-4B gồm 3 thành phần chính:

    1. Vision Transformer (ViT): Trích xuất đặc trưng thị giác từ ảnh (≈ 415M tham số).
    2. Projector / Merger: Khối ánh xạ vector từ không gian ViT sang không gian nhúng của LLM. Trong Qwen3-VL, khối này gồm visual.merger (≈ 27M tham số) và visual.deepstack_merger_list (≈ 82M tham số, kết nối sâu từ các lớp 5, 11, 17 của ViT) → Tổng cộng ≈ 109M tham số.
    3. Large Language Model (LLM): Xử lý suy luận ngôn ngữ và sinh token toạ độ (≈ 4.0B tham số).

Chúng ta thiết kế 3 thí nghiệm đối chứng có kiểm soát để trả lời câu hỏi trên:

    E1: Chỉ cập nhật LoRA trên LLM (252 modules). Đóng băng hoàn toàn ViT và Projector.
    E2: Cấu hình E1 + Mở huấn luyện đầy đủ Projector (109M tham số đưa về float32).
    E3: Cấu hình E2 + Bổ sung LoRA trên các khối Attention và MLP của ViT (thêm 96 modules LoRA).

So sánh các khối được cập nhật trong E1, E2, E3

Thí nghiệm E1

Giải nghĩa từ khóa chuyên môn

    DeepStack Merger: Kỹ thuật trích xuất đặc trưng đa tầng trong Qwen3-VL. Thay vì chỉ lấy vector ở lớp cuối cùng của ViT, mô hình trích xuất đặc trưng ở cả tầng nông và tầng trung gian (lớp 5, 11, 17), giúp bảo toàn thông tin chi tiết về các vật thể nhỏ (rất quan trọng đối với ổ gà và vết nứt có diện tích chỉ ≈ 0.7% khung hình).
    Float32 Projector: Các tham số của merger phải được ép kiểu về torch.float32 khi huấn luyện. Nếu để ở fp16, việc tích luỹ gradient qua nhiều tầng DeepStack rất dễ gây hiện tượng tràn số (numerical underflow/overflow), dẫn đến Loss = nan.
    Cạm bẫy lưu trữ Projector: Khi dùng thư viện PEFT, lệnh model.save_pretrained() chỉ lưu adapter LoRA. Projector là tham số gốc được mở requires_grad=True, do đó bắt buộc phải lưu riêng ra file .pt. Nếu quên, khi suy luận bạn sẽ nạp lại Projector gốc chưa huấn luyện, khiến kết quả E2/E3 bị kéo tụt về giống hệt E1!

from peft import LoraConfig, get_peft_model


def apply_setup(model, setup_name: str):
  for p in model.parameters():
    p.requires_grad = False
  model.enable_input_require_grads()

  # 1. Mục tiêu LoRA
  target_modules = [
      "q_proj",
      "k_proj",
      "v_proj",
      "o_proj",
      "gate_proj",
      "up_proj",
      "down_proj",
  ]
  if setup_name == "E3":
    target_modules += ["qkv", "linear_fc1", "linear_fc2"]

  lora_config = LoraConfig(
      r=16,
      lora_alpha=32,
      lora_dropout=0.05,
      target_modules=target_modules,
      bias="none",
      task_type="CAUSAL_LM",
  )
  peft_model = get_peft_model(model, lora_config)

  # 2. Mở Projector cho E2 và E3
  if setup_name in ["E2", "E3"]:
    for name, param in peft_model.named_parameters():
      if "visual.merger" in name or "visual.deepstack_merger_list" in name:
        param.data = param.data.to(torch.float32)
        param.requires_grad = True

  return peft_model

Chặng 6 — Thử thách Thưởng E5 (+10 điểm): GRPO với Reward IoU
Bản chất và vấn đề cần giải quyết

Huấn luyện có giám sát (SFT) dạy mô hình bắt chước phân bố token của nhãn, nhưng không trực tiếp tối ưu hóa mục tiêu hình học của bài toán là chỉ số IoU (Intersection over Union).

Trong thí nghiệm E5, bạn áp dụng thuật toán Group Relative Policy Optimization (GRPO) — phương pháp học tăng cường hiện đại được sử dụng để huấn luyện DeepSeek-R1. Với mỗi ảnh đầu vào, mô hình sinh ra một nhóm gồm 4 phương án dự đoán (num_generations=4), sau đó tính phần thưởng cho từng phương án dựa trên chất lượng bounding box so với ground truth để cập nhật chính sách mà không cần mạng Critic (Value Network) cồng kềnh.

Tổng IoU các cặp khớp

Reward = 0.2 + 0.8 * (Tổng IoU) / max(Số GT, Số Pred, 1)

Phần thưởng [0.2, 1.0]
Hiện tượng Hack phần thưởng (Reward Hacking)

Nếu hàm reward thiết kế không chặt chẽ, mô hình sẽ tìm ra "đường tắt" để tối đa hóa điểm thưởng mà không thực sự phát hiện đúng vật thể:

    Chiến thuật trả về rỗng []: Nếu ảnh không có hư hại và mô hình đoán [], thưởng nhận được là 1.0. Nếu hàm thưởng quá dễ dãi, mô hình sẽ lười biếng trả về [] cho mọi ảnh.
    Chiến thuật bao trùm (Giant Box): Sinh ra một box khổng lồ chiếm trọn màn hình [0, 0, 1000, 1000] để hy vọng ăn điểm IoU với mọi box nhỏ.
    Biện pháp ngăn chặn: Mẫu số max(N_gt, N_pred, 1) sẽ phạt nặng mọi box thừa sinh ra, đồng thời ngưỡng IoU ≥ 0.5 lập tức triệt tiêu điểm của các box khổng lồ có diện tích quá chênh lệch.

    1. Viết hàm thưởng và bộ kiểm thử đơn vị độc lập:

from scripts.score import iou_xyxy, parse_output


def compute_reward(completion: str, gt_boxes: list[dict]) -> float:
  pred = parse_output(completion)
  if pred is None:
    return 0.0  # JSON hỏng
  if not gt_boxes and not pred:
    return 1.0  # Cả hai cùng rỗng

  total_iou = 0.0
  all_labels = {g["label"] for g in gt_boxes} | {p["label"] for p in pred}
  for lab in all_labels:
    g = [x["bbox"] for x in gt_boxes if x["label"] == lab]
    p = [x["bbox"] for x in pred if x["label"] == lab]
    pairs = sorted(
        (
            (iou_xyxy(a, b), i, j)
            for i, a in enumerate(g)
            for j, b in enumerate(p)
        ),
        reverse=True,
    )
    used_g, used_p = set(), set()
    for v, i, j in pairs:
      if v < 0.5:
        break
      if i in used_g or j in used_p:
        continue
      used_g.add(i)
      used_p.add(j)
      total_iou += v

  denom = max(len(gt_boxes), len(pred), 1)
  return 0.2 + 0.8 * (total_iou / denom)
